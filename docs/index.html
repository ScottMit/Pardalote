Why Pardalote

Made for people who think with their hands

Pardalote was built for design studios and classrooms — places where an idea moves back and forth between a breadboard and a browser tab.

Two languages, equal partners

You write real Arduino code and real JavaScript. Neither side is privileged — both get control of the hardware, and both can lead.

Multi-user by default

One Arduino can talk to many browsers, and one browser to many Arduinos. A whole class can connect to the same device.

Always in sync

Connect at any moment and you're up to date: the Arduino tells every new browser its current state the instant it joins.

WiFi or wires

Over WiFi, any device on your network can join — laptop, tablet, phone. No router handy? The same code runs over the USB cable instead. Either way, no server and no Node.js.

Open source

Built on free and open platforms, and free itself. Published under GPL-3.0 — use it, read it, fork it. It belongs to the people who use it.

No setup maze

One script tag in the browser, one library on the board. No build tools, no toolchain to fight before you can blink an LED.

How small is small?

A complete Pardalote project

sketch.ino — the whole Arduino side
#include <Pardalote.h>

void setup() {
  Pardalote.begin();
}

void loop() {
  Pardalote.run();
}
sketch.js — blink from the browser
const arduino = new Arduino();
arduino.connect('192.168.1.42');

arduino.on('ready', () => {
  arduino.pinMode(13, OUTPUT);
  arduino.digitalWrite(13, HIGH);
});

The JavaScript API mirrors Arduino's own function names — pinMode, digitalWrite, analogRead — so what you learn on one side carries straight over to the other.

In the classroom

Built for teaching, tested in studios

Pardalote grew out of design education: students prototyping IoT ideas need to see cause and effect quickly, on both sides of the link. It plays especially well with p5.js, building on Processing and Wiring's (Arduino) shared heritage.
